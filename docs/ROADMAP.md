## 两个待你拍板的（不做就上不了线）

### 1. 模型自托管：文件放哪

现在 `NEXT_PUBLIC_WASM_BASE` / `SEG_MODEL` / `FACE_MODEL` / `HAND_MODEL` 全指向
jsdelivr 和 storage.googleapis.com。**国内大概率加载不出来**，用户看到的是页面卡在
「Loading the person-segmentation model…」——不报错，就是一直转。

| 方案 | 需要什么 | 说明 |
|---|---|---|
| Vercel Blob | `BLOB_READ_WRITE_TOKEN` | 和部署同一家，最省事，几十 MB 在免费额度内 |
| Cloudflare R2 | account id + bucket + API token | README 推荐的，国内访问比 Vercel 好 |
| 塞进 `public/` | 不需要凭据 | 最快能验证链路，但每次部署传十几 MB，仓库变大 |

⚠️ **别把这几个变量直接填成 `/vendor/...`**：`public/vendor` 在 `.gitignore` 里，
产物里没有这些文件，那样会让 `/vendor/*` 全部 404，比现在还糟。README 特意标了这个坑。

### 2. iOS 真机验证

生产 URL 已经有了，拿手机开一下就能验这三条（`PRD` 7.2 把 iOS Safari 标成最大风险，
这个判断是对的）：

1. **能不能录出 mp4。** 录制按钮上写着实际拿到的容器格式。这条不通，产品对 Reels
   创作者就不成立。
2. **移动端帧率。** 引擎的降级触发条件是 `pointer: coarse`，这个启发式很粗糙。
   `signal-lost` 和 `finger-flowers` 是目前最重的两个（各跑两个模型），先拿它们试。
3. **微信内置浏览器。** iOS 微信的 `getUserMedia` 限制多，现在既没检测也没引导。

桌面 Chrome 测不出这三条 —— iOS 上所有浏览器内核都是 WebKit。

## ③ 泡泡模拟器（唯一还没动的大件）

指尖发射带彩虹色散的肥皂泡，物理飘浮、相互遮挡、表面折射摄像头画面，
右下角控制面板（强度四档 + 数量 + 透明度）。

它和已经做完的「指尖种花」的**分岔点不是难度，是状态的性质**：

|  | 指尖种花（已完成） | 泡泡 |
|---|---|---|
| 状态 | 只追加、互不影响 | **可变、互相作用** |
| 新渲染路径 | 不需要 | **需要** |

### 四件事，按依赖排序

**a. instanced quad 取代 `gl_PointSize`**（`EFFECT-QUALITY` P-6）

现在圆点走 `gl_PointSize`，它屏幕对齐、**不能旋转**，尺寸还有实现上限，
画不了参考素材里两百像素的大泡泡。液体那条线已经是 instanced quad 了，照它改。

**b. 深度排序 + 正确的 alpha 合成**

现在两个粒子材质都是 `depthTest: false` + `depthWrite: false`，**完全没有排序**，
混合顺序就是缓冲区顺序。小圆点看不出来，18 个大泡泡叠在一起立刻露馅。

**c. 可变状态 + 交互**

泡泡会飘、会撞、会破。「破了」是不可逆的，而且由外部输入（指尖）触发 ——
这不是 append-only，是每帧修改一池对象 + 指尖×泡泡的碰撞检测。

要确定性就得定步长积分，而且**对浮点求和顺序敏感**。`stepTo` 已经有了（定步长），
但 `TrailBuffer` 那套「写进去不再改」的简单性在这里不成立，得重新想一遍
「怎么让一池会互相影响的对象仍然可回放」。**这是这一块唯一有设计风险的部分。**

**d. `controls` 对非粒子模板打通 + 离散控件**

`resolveControls` 现在只在 `templateType === "particle"` 的分支里被调用 ——
overlay 模板写了 `controls` 就是几个拖了没反应的滑块，而且不报错。
另外四档预设（Mild/Medium/Strong/Extreme）是**离散**控件，schema 里只有连续的
min/max/step。

### 便宜的部分

**折射比听起来便宜**：直接采源视频纹理就行（那正是想要的效果 —— 折射背景），
不用读回帧缓冲。彩虹色散是薄膜干涉，按边缘距离算，shader 里几行。
真正贵的是 a/b/c 三条。

### 一个提醒

18 个大泡泡**不是粒子系统的形态**。那个池子是 9000 容量的小圆点，为「一帧发几百个」
设计的。别因为叫「粒子」就硬塞进 `ParticleSystem`。

## 状态层一通就顺带解锁的

`stepTo` + 定步长 + 固定时间网格采样这套地基（见 `src/engine/trail.ts` 的注释）
不是为某一个模板付的钱。`EFFECT-QUALITY` 里这两条现在都变便宜了：

- **P-2 积雪累积**：雪落到肩膀上盖一层，慢慢变厚，人一动就掉。
  原文写的「设计要先解决这个再动手」指的就是无历史性这堵墙。
- **P-8 液体湿痕**：同一套累积缓冲，换个材质渲成湿痕。

两条都要**累积缓冲**（一张跨帧的贴图），比轨迹的环形缓冲重，但纪律是同一套。

## 观感上还欠的

- **暗边参数没在真白墙上调过。** 雪的暗边是在离线 harness 的浅灰背景上定的
  （`src/engine/particles.ts` 里的 rim），真机对着白墙要再调一轮。
- **`crying` 的眼泪在深色皮肤上偏「蓝色贴纸」。** `screen` 混合在浅肤色上像湿光，
  在偏暗的照片上不成立。换了真人 fixture 之后才暴露出来的。
- **`X-1` 全局后期**（bloom / grain / 暗角）一条都没做。`EFFECT-QUALITY` 说它
  「一个全局 look pass 会同时抬高三个类目」，判断是对的，但要计入移动端的降级档位。
